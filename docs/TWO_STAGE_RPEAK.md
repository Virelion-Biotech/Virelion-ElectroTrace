# Two-stage R-peak detection

ElectroTrace 1.5 adds a second-stage verifier for the existing high-recall R-peak candidate detector.

## Motivation

The first-stage detector was externally benchmarked on MIT-BIH Arrhythmia records at 75 ms matching tolerance. It produced high recall but too many false positives. The intended architecture is therefore:

```text
Stage 1: high-recall candidate generation
            ↓
Stage 2: candidate verification / false-positive suppression
            ↓
Final R-peak candidates
```

The second stage does **not** attempt to recover beats missed by Stage 1 unless the separately named recovery mode is explicitly enabled and evaluated as a distinct experiment.

## Features

Candidate features include normalized peak amplitude, Stage-1 prominence, half-prominence width, local slope, local RMS/crest factor, frequency-energy fractions, left/right asymmetry, neighboring RR features, and normalized local morphology.

These are deliberately local, interpretable features rather than a deep model so the verifier can be trained and inspected on modest datasets.

## Training and calibration

`CandidateSuppressor` uses a balanced random forest. Training labels are generated by matching Stage-1 candidates to independent accepted/reference R-peak locations within a configurable tolerance.

For rigorous record-level benchmarking, model fitting and threshold calibration are separated by **complete records**. The calibration records are not included in the model-fit records, and the final evaluated verifier is not refit on the calibration records after threshold selection. Threshold selection must never use held-out evaluation records.

The operating threshold targets high training sensitivity, but its threshold-selection evidence comes only from the prespecified held-out calibration records. If the required record/class constraints cannot be satisfied, calibration fails rather than silently falling back to a leaking split.

The included MIT-BIH two-stage benchmark script performs record-level separation before fitting:

```bash
python scripts/benchmark_two_stage_mitdb.py \
  --data-dir .cache/physionet/mitdb \
  --output validation_reports/mitdb_two_stage_validation.json
```

It reports Stage-2 performance only on evaluation records and stores the trained verifier as a separate `.pkl` artifact. Never load an untrusted pickle file.

## Research safeguards

- records, not individual beats, are the split unit
- fit and calibration records are disjoint
- evaluation records are untouched during fit and threshold selection
- Stage 1 remains available for direct comparison
- Stage 2 is not described as clinical-grade
- any recovery experiment is separately identified because it changes the effective candidate-generation regime

## Intended next step

Run the two-stage model on a completely frozen external evaluation set, report Stage 1 vs Stage 2 side-by-side, preserve all failed records, and inspect difficult records without changing the frozen threshold or model before deciding whether additional features or another model class are justified.
