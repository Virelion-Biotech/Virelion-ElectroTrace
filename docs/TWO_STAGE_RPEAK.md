# Two-stage R-peak detection

ElectroTrace 1.5 adds a second-stage verifier for the existing high-recall R-peak candidate detector.

## Motivation

The first-stage detector was externally benchmarked on all 48 MIT-BIH Arrhythmia records at 75 ms matching tolerance. It produced very high recall but too many false positives. The intended architecture is therefore:

```text
Stage 1: high-recall candidate generation
            ↓
Stage 2: candidate verification / false-positive suppression
            ↓
Final R-peak candidates
```

The second stage does **not** attempt to recover beats missed by Stage 1.

## Features

Candidate features include:

- normalized peak amplitude
- Stage-1 prominence
- half-prominence width
- maximum and mean local slope
- local RMS and crest factor
- low/QRS/high/very-high frequency energy fractions
- left/right energy and amplitude asymmetry
- previous/next RR intervals and normalized RR ratios
- a 64-point normalized local morphology representation

These are deliberately local, interpretable features rather than a deep model so the verifier can be trained and inspected on modest datasets.

## Training

`CandidateSuppressor` uses a balanced random forest. Training labels are generated by matching Stage-1 candidates to independent accepted/reference R-peak locations within a configurable tolerance.

The default operating threshold is selected on the training data to achieve a target recall of 99.5% whenever the training predictions permit it. Threshold selection must **never** be performed on the held-out evaluation records.

The included MIT-BIH two-stage benchmark script performs record-level splitting before fitting:

```bash
python scripts/benchmark_two_stage_mitdb.py \
  --data-dir .cache/physionet/mitdb \
  --output validation_reports/mitdb_two_stage_validation.json
```

It reports Stage-2 performance only on held-out records and stores the trained verifier as a separate `.pkl` artifact. Never load an untrusted pickle file.

## Research safeguards

- records, not individual beats, are used as the train/test split unit
- the held-out records are never used to choose the operating threshold
- the original Stage-1 detector remains available for comparison
- the verifier is not described as clinical-grade
- false-negative recovery is outside the scope of this stage

## Intended next step

The next scientific task is to run the two-stage model on the full MIT-BIH database, compare Stage 1 vs Stage 2 side-by-side, inspect the difficult records (especially 207 and other low-PPV recordings), and only then decide whether additional features or a different model class are justified.
